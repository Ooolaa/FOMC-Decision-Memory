# 問題與解法摘要

開發過程中真正踩到的坑，以及怎麼修的。每一項都附可重跑的驗證方式——被問到時可以當場證明。

排序不是時間順序，是**嚴重程度**：前面幾項如果沒發現，系統會安靜地給出看起來合理但錯誤的答案。

---

## 一、最嚴重的：語料涵蓋率有年代偏差

**症狀**　用 2008 年 9 月（雷曼倒閉）的總體數據測試，檢索出的「條件最相近會議」
前八名全是 2023、2017、2012 年的「維持」會議。10/8 與 10/29 兩次緊急降息
**完全不在候選池裡**。

**原因**　段落抽取規則靠 `Participants' Views on Current Conditions` 這個標題，
和「A few participants…」這類量詞開頭來辨識政策討論段落——但這兩個都是
**2009 年以後才固定的體例**。結果：

| 年代 | 每場平均可檢索段數（修正前） |
| --- | --- |
| 2000–2004 | 2.6 |
| 2005–2009 | 4.9 |
| 2012–2026 | 17–18 |

整個危機年代在檢索池裡幾乎不存在——而危機年代正好是降息集中的地方。這解釋了
為什麼降息召回率一直上不去。

**解法**　段數不足 10 的會議，改用政策詞密度最高的段落補足
（`build_rag_index.py` 的 `pick_minute_chunks`）。

**結果**　各年代平均段數 11.0 / 11.3 / 16.4 / 17.5 / 17.1，落差從 7 倍縮到 1.6 倍；
降息召回率 32% → 35%。

```sh
cd 04_RAG_Vote_Simulator && python3 diag_coverage.py
```

## 二、多數類靠鄰居數量取勝

**症狀**　把所有命中會議加權統計，方向準確率 **63.8%**，**輸給**「全部猜維持」的
66.5% 基準。

**原因**　語料 244 場裡「維持」佔 147 場。命中會議越多，多數類的權重就越大——
這不是在檢索相似情境，是在數哪一類比較常見。

**解法**　去重重排後**只採計分數最高的 8 場**（`PARAMS.topM`）。

**結果**　63.8% → 72.9%。

## 三、BM25 沒有方向概念

**症狀**　「通膨遠高於 2% 目標」的查詢，照樣命中大談通膨**低於**目標的 ZIRP 時期紀要。

**原因**　BM25 只看詞彙重疊。「inflation」「objective」「target」在兩種相反的敘述裡
都會出現。

**解法**　每場會議帶上條件標籤（通膨偏高／偏低、勞動市場緊俏／轉弱…），
標籤相反的會議依比例扣分（`PARAMS.delta = 1.5`）。

**結果**　72.9% → 74.7%（當時的數字，加動量標籤後為 74.2%）。

## 四、一個加了又退掉的解法

**做了什麼**　為了修第一項的 2008 檢索問題，加上「相同標籤加分」γ=0.6——條件標籤
相同的會議加權。

**看起來很成功**　2008 情境的降息機率 17.5% → **43.8%**，2008-03-18 那場真正的降息
會議進了前六名。

**但是**　拿 2020 年的 COVID 情境回頭驗，結論被翻成**升息 45.9%**——比修正前更糟。

**原因**　標籤描述的是「水準」不是「衝擊」。2020-03 的情境標籤是「勞動市場緊俏、
成長穩健、金融條件緊縮」——帳面上完全正確。加分機制讓前兩個常見標籤蓋過第三個
關鍵標籤，把 2016／2023 那些景氣不錯的升息會議拱到前排。留一法回測也偏好 γ=0。

**決定**　**退掉**（`PARAMS.gamma = 0`，程式碼保留這條路徑並註明原因）。

用單一案例調出來的參數，換個案例就會反咬。這一項留在這裡，是因為它比任何一個
成功的修正都更能說明這個專案的取捨標準。

## 五、水準 vs 衝擊：加入動量特徵

**症狀**　2008 年 10 月降息的理由是「油價大跌、通膨壓力開始緩解」，但當時 CPI
仍有 4.9%。查詢照水準值寫成「通膨遠高於目標」，與降息聲明的措辭**語意相反**，
把該找到的會議推得更遠（10/7 排到第 58 名）。

**解法**　新增三個動量欄位（CPI／信用利差／失業率的 3 個月變化），只進入查詢生成與
條件標籤，**不進入計量模型**——R5 的 pooled ordered-logit 是凍結的七特徵 artifact，
加特徵等於重新訓練，會破壞它與封存標籤的可驗證關係。

**結果**　六個歷史危機案例 3/6 → **4/6**，留一法回測不變（74.2%）。2008-10-29 的
類比會議從「2023-11-01、2017-09-20、2012-06-20…」變成
「**2008-10-29、2008-10-07、2008-12-16、2008-03-18**」。

```sh
cd 04_RAG_Vote_Simulator && python3 eval_momentum.py
```

**仍然答錯的兩個案例，原因也寫進文件**：2020-03 的降息是基於疫情的前瞻判斷
（Fed 自己的聲明說「the U.S. economy came into this challenging period on a strong
footing」）；2022-06 則是檢索側答對了、計量模型把它拉回來。

## 六、政策行動標記：三種誤判

從聲明原文判斷「這場是升息還是降息」，比想像中難：

| 誤判 | 例子 | 解法 |
| --- | --- | --- |
| 前瞻指引被當成決策 | 2015 年的維持會議寫「it will be appropriate to raise…」被標成升息 | 對每個 funds-rate 句評分，decision cue（decided/voted/today）對抗 guidance cue |
| 資產負債表決策被當成升息 | 「decided to increase the size of the balance sheet」 | 只錨定含 federal funds rate 的句子 |
| 異議者的偏好被當成決策 | 「preferred to maintain the existing target range」 | 排除 Voting for/against 段落 |

**驗證**　與 R5 封存標籤在 121 場重疊會議中**一致 120 場**。唯一差異是 2020-03 的
臨時降息，R5 標為「維持」，本工具依聲明原文標為「降息」。

```sh
cd 04_RAG_Vote_Simulator && python3 check_index.py
```

## 七、語料解析的三個小坑

- **CSV 是雙重 UTF-8 編碼**：en dash 在檔案裡是 `c3 a2 c2 80 c2 93`。用替換表修不掉，
  因為內層位元組落在不可列印的控制字元上。解法是 latin-1 往返修復，而且要**逐段修**——
  一份 50 KB 的紀要裡只要有一個字元不能編碼，整串往返就會放棄，全文的破折號都留著。
- **投票名單的正則被中間名切斷**：`Jerome H. Powell` 的句點讓句子分割器提早結束。
  改用 landmark slicing（從 were/was/: 之後切到下一個地標片語）。
- **多位委員共用一句異議理由**：「A、B、C, who preferred to raise…」被切成三份，
  方向判定失準。改成只在段落有多個 reason clause 時才切分。

## 九、影片管線（沒有 ffmpeg 的情況下）

- **螢幕錄影權限被系統擋掉**：`screencapture -v` 沒有輸出檔。改成 Playwright 逐格擷取
  真實操作 + AVFoundation 合成，全程只用系統內建工具。
- **會議現場拍到全白**：artboard 在 sandboxed iframe 裡，載入後約 4 秒才掛載完。
  改成輪詢到 12 個座位都出現才開拍，並用畫面上的「重播會議」按鈕讓動畫從頭播
  （reload 的話又要重等掛載）。
- **一張靜止畫面會跨好幾條字幕**：一格撐 15 秒卻只畫一條字幕就錯了。改成依字幕邊界
  把該格切成數格重畫（348 格擷取 → 391 格輸出）。
- **時間戳撞號**：一條字幕的結束與下一條的開始是**同一個時間點**，浮點誤差產生兩個
  幾乎相同的時間戳，AVAssetWriter 直接拒收整支影片。解法是先量化到時間刻度
  （1/600 秒）再去重。
- **`say` 把百分號唸壞**：`74.2%` 唸成沒講完的「七十四點二百分之」。中文語序是
  「百分之」在數字**前面**，所以合成前用正則轉成 `百分之74.2`；字幕仍顯示 `74.2%`。

## 十、交付包本身就有的問題（不是我們造成的）

`AGENTS.md` 原本要求 `02_Application/` 必須剛好 **1,102 個檔案**，與 `SOURCE_FILES.txt`
完全一致。實際上只有 **1,101 個**——缺 `專案導覽_zh-TW.md`，而 AGENTS.md 還指名
要讀它。

這在動工前就是如此（該目錄所有檔案的 mtime 都停在解壓時間），
`shasum -c SHA256SUMS.txt` 仍全數通過。動工前先跑一次 diff 把基準記錄下來，
才不會把它誤認成自己弄壞的。

**現況**：公開釋出時 manifest 已依 `engineering_handoff.py` 的原格式重產為
**1,005 筆**，這道缺口一併校正，下面這條 diff 現在是零差異。

```sh
cd 02_Application && find . -type f -not -name '.DS_Store' -not -path '*/__pycache__/*' \
  | sed 's|^\./||' | LC_ALL=C sort \
  | diff - ../01_Release-Handoff/01_Manifests-and-Integrity/SOURCE_FILES.txt
```

## 回測數字的完整脈絡

留一法（以每場會議的經濟情勢敘述為查詢，排除該場及前後各 2 場）：

| 階段 | 準確率 | 降息召回 |
| --- | --- | --- |
| 全部命中加總 | 63.8% | 6% |
| 多數類基準（全猜維持） | 66.5% | 0% |
| ＋只採計前 8 場 | 72.9% | 32% |
| ＋矛盾標籤扣分 | 74.7% | 32% |
| ＋涵蓋率修正、動量特徵（**出貨設定**） | **74.2%** | **35%** |

最後一列準確率略降 0.5 個百分點，但降息召回率上升、且六個歷史危機案例從 3/6 進步到
4/6——這是刻意的取捨：對這個題目來說，**能認出危機**比小數點後的準確率重要。

**這個數字仍然偏樂觀**：回測的查詢是各場會議自己的聲明原文，用字自然跟同年代一致；
互動介面的查詢是用現代 Fed 語彙合成的，會系統性偏向詞彙相近的近期會議。這一層
誤差回測量不到。

```sh
cd 04_RAG_Vote_Simulator
python3 eval_tags.py       # 留一法回測
python3 eval_momentum.py   # 六個歷史危機案例
python3 check_index.py     # 行動標記與封存標籤比對
```
